## Proje

Tek galeriye ait premium oto galeri sitesi: Razor vitrin + araçların Sahibinden ayrıntısında girildiği yönetim paneli. Altyapı GoraDigitalSignage'dan alındı; **tenant yok, çoklu dil yok (yalnız Türkçe)**. Ürün kararları aşağıda "Kararlar" bölümündedir.

| Proje | Görevi |
|---|---|
| `FatihTasci.Core` | Entity, enum, DTO + validator, servisler, repository/UnitOfWork, middleware |
| `FatihTasci.Data` | `AppDbContext`, `DbSeeder` (şema SQL betikleriyle, `Database/`) |
| `FatihTasci.Server` | Admin JSON API (`/api/*`), vitrin Razor sayfaları, medya (`/media`), panelin derlenmiş hali (`/panel`) |
| `FatihTasci.Admin` | Yönetim paneli: React 19 + TS + Vite + shadcn/ui |

## Komutlar

- Server: `dotnet run --project FatihTasci.Server` → http://localhost:5080 (vitrin), http://localhost:5080/panel (panelin derlenmiş hali)
- Panel geliştirme: `cd FatihTasci.Admin && npm run dev` → http://localhost:5173/panel/ (`/api`, `/media` ve `/images` Vite proxy'si ile 5080'e gider, CORS yok)
- **Portlar sabittir:** Server 5080 (`launchSettings.json`), panel 5173 (`vite.config.ts`, `strictPort`); başka porta kaymazlar (`.claude/launch.json`'da `autoPort: false`).
- **Başlatırken eski süreç kapatılır:** `scripts/start-server.ps1` 5080'i dinleyen ve `bin\Debug`'ı kilitleyen eski sunucuyu kapatıp `dotnet run` yapar; panelde `npm run dev` öncesi `predev` 5173'ü boşaltır (`scripts/free-port.ps1`). Sunucuyu terminalden `powershell -File scripts/start-server.ps1` ile başlatın.
- **Visual Studio:** `FatihTasci.Server` başlangıç projesi, profiller `launchSettings.json`'da: **Vitrin** (5080'i açar) ve **Panel** (Vite'ı da başlatır, `http://localhost:5173/panel/`'i açar; `DevTools:StartViteDevServer`, `Helpers/ViteDevServer.cs`). Debug derlemeden önce `StopPreviousServer` MSBuild adımı eski sunucuyu kapatır (`FatihTasci.Server.csproj`). `server-verify` (5081, `-c DebugVerify`) yalnız 5080'deki sunucu açıkken doğrulama içindir; `bin/Debug` kilitliyken ayrı klasöre derler. `panel-verify` (5174) Vite'ı `VITE_SERVER_URL` ile 5081'e bağlar; geliştirme girişi hazır dolu gelir, 5173'e dokunmadan panel doğrulanır.
- Panel derleme: `npm run build` (çıktı `FatihTasci.Server/wwwroot/panel`), `npm run lint`
- Yayın (Windows / IIS paylaşımlı barındırma, FTPS): tek komut `powershell -ExecutionPolicy Bypass -File scripts/deploy/deploy.ps1` (`-Panel` önce paneli derler, `-Property IncludeDemoData=true` `Assets/Seed`'i pakete katar, `-All` tüm paketi, `-WhatIf` yalnız listeyi gösterir): `dotnet publish`, sonra `ftp-deploy.ps1` yalnız son başarılı yüklemeden bu yana içeriği değişen dosyaları yükler (yerel liste `%LOCALAPPDATA%\FtpDeploy`, SHA-256; `-Files a,b,Klasör` yalnız verilenleri). `publish/` repoya girmez. **`scripts/deploy/` ortaktır, projeden bağımsızdır**: başka projeye (ör. aynı sunucuda başka FTP kullanıcısıyla Reform İnovasyon sitesi) olduğu gibi kopyalanır; projeye özel her şey `scripts/deploy.json`'da (`Profile` hesap adı, `ServerProject`, `PanelDir`, `PublishDir`, `SettingsFile` + `RequiredSettings` / `WarnIfTrue` yayın ayarı kontrolü, `LogsPath`). FTP hesabı proje başına bir kez `scripts/deploy/ftp-login.ps1 -FtpHost <sunucu> -User <kullanıcı> -RemotePath /` ile kaydedilir (önce bağlanıp dener; `%APPDATA%\FtpDeploy\<Profile>.xml`, şifre DPAPI ile yalnız o Windows kullanıcısına şifreli; `-Remove` siler); kayıt yoksa şifre terminalde sorulur, komut satırında hiç geçmez. Bu sitenin FTP girişi doğrudan site köküne açılır (`/httpdocs` yok). Betik önce `app_offline.htm` koyar, dosyaları 20'lik gruplarla tek bağlantıda gönderir (yarıda kalırsa tekrar çalıştırınca kalanlar gider), sonra siteyi açar; sunucudaki `Storage/`'a (fotoğraflar, loglar) dokunmaz, pakette olmayan dosyayı silmez. Son hata kayıtları `scripts/deploy/ftp-logs.ps1`. Projeye özel betikler `scripts/` kökünde: `free-port.ps1`, `start-server.ps1`, `export-site-seed.ps1` (yereldeki site ayarları ve showroom fotoğraflarını `Server/Assets/Seed/Site`'a aktarır, açılışta `SiteSeeder` içe alır: yalnız eksik ayar anahtarını ekler, fotoğrafı yalnız yeni eklenen sahneye koyar; pakete `IncludeDemoData` ile girer). Yayın ayarı `FatihTasci.Server/appsettings.Production.json`'da değişir, `dotnet publish` onu pakete kopyalar (pakettekini elle düzenlemek sonraki publish'te kaybolur). Paket yalnız win-x64 / win-x86 yerel kütüphanelerini içerir, yerel `.pdb`'ler ve `appsettings.Development.json` alınmaz (`TrimPublishRuntimes`, csproj); Linux için `-p:PublishWindowsOnly=false`. `appsettings.Production.json` gerçek bağlantı dizesi / şifre içerdiği için commit edilmez, yalnız yerelde ve sunucuda doldurulur.
- Şema betiği (migration yok, bkz. "Veritabanı"): `dotnet ef dbcontext script --project FatihTasci.Data --startup-project FatihTasci.Server -o Database/FatihTasci-schema.raw.sql`, sonra başlık / `SET` satırları eklenip BOM'suz ASCII `Database/FatihTasci-schema.sql` olarak kaydedilir.

## Ortam ve ayarlar

- .NET 10 (`net10.0`), SQL Server (geliştirmede LocalDB). Şema EF migration ile değil SQL betikleriyle kurulur (aşağıda "Veritabanı"); açılışta yalnız `DbSeeder.SeedAsync` çalışır, şema yoksa uygulama betiği çalıştırın diyen hatayla durur. Seed adımları `Data/Context/Seed/`'de alana göre: `Account/AccountSeeder` (panel kullanıcıları), `Vehicle/VehicleSeeder` (renk, donanım, katalog; katalog `CatalogSeedData.cs`, SpareParts'tan), `Site/SiteSeeder` (ayarlar, showroom sahneleri, dışa aktarılan site verisi), `Listing/ListingSeeder` (galerinin ilanları), `Delivery/DemoDeliverySeeder`; verileri yanlarındaki `*SeedData`'da. Seed yalnız `Seed:Enabled` açıkken çalışır (`appsettings.json`'da kapalı, Development ve Production'da açık) ve **yalnız ekler, hiçbir şeyi güncellemez ve silmez** (kullanıcı kararı, 2026-11-20): koddaki kayıt sabit Id'siyle eklenir; Id'si ya da benzersiz alanı (renk adı, kategori + donanım adı, marka / model / paket slug'ı, sahne başlığı, ayar anahtarı, kullanıcı e-postası; Türkçe, büyük-küçük harf farksız) veritabanında varsa atlanır (`SeedHelper.AddMissingAsync`). Panelde değişen kayıt (ad, sıra, şifre, rol, boş bırakılan ayar dahil) olduğu gibi kalır, silinmiş (`IsDelete`) kayıt geri gelmez; koddaki bir kayıt sonradan değişirse mevcut veritabanlarına yansımaz (panelden ya da betikle değiştirilir). Koddaki listeye eklenen yeni kayıt mevcut veritabanlarına (canlı dahil) bir sonraki açılışta eklenir: renk listenin, donanım kategorinin sonuna. Seed Id'leri 100000'in altındadır, seed'li int tablolarda identity 100000'den başlar (`AppDbContext.SeedIdLimit`, `Database/Changes/001_SeedIdAraligi.sql`); yeni seed kaydına o tabloda kullanılmamış bir Id verilir. Eski (ada göre) seed ile kurulmuş veritabanında Id'ler eşleşmez: böyle veritabanı betiğin notundaki gibi yeniden kurulur. Yeni seed verisi eklerken de bu ilke korunur. Örnek teslimatlar `DemoData:Enabled` açıkken eklenir (geliştirmede açık; `appsettings.json`'da kapalı), ayar kapatılınca silinmez (gerekirse panelden silinir); fotoğraflar stok olduğu için yayın paketine yalnız `-p:IncludeDemoData=true` ile girer (`KAYNAK.md`). Örnek (başka galerinin) araç seed'i kaldırıldı; yerine galerinin kendi sahibinden ilanları gerçek veri olarak seed edilir (kullanıcı kararı, 2026-11-20): `Listing/ListingSeedData` (ilan başına fotoğraf klasörü, katalog / renk / donanım adları, sabit Guid `Vehicle.Id`; yeni ilana yeni Guid). Fotoğraflar `Server/Assets/Seed/Vehicles/{klasör}`'de, dosya adı sırası ilandaki sıradır (ilki kapak), panel yüklemesiyle aynı yoldan işlenir (filigran ayara göre); açıklama editör biçimindedir ve `VehicleService.SanitizeDescription`'dan geçer; danışmanı verilmeyen ilanın danışmanı Hasan Korkmaz'dır (`ListingSeedData.AdvisorId`, seed'de Personel hesabı; pasifse Yönetici), ilanlar tek tek kaydedilir (ilan no listedeki sırayla). Id'si veritabanında olan ilan (silinmiş dahil) atlanır. İlan yayında eklenir; canlıya fotoğraflarla birlikte yalnız `-p:IncludeDemoData=true` paketiyle çıkar (o paket örnek teslimatları da taşır). sahibinden fotoğraflarında portalın çapraz filigranı vardır.
- **Paylaşımlı barındırma (IIS):** `FatihTasci.Server/web.config` istek sınırı 300 MB (`Program.MaxUploadBytes` ile aynı; IIS varsayılanı 30 MB), `IISServerOptions.MaxRequestBodySize` de aynı. Data Protection anahtarları (vitrin formlarının antiforgery'si) `Storage/private/keys`'e kalıcı yazılır, uygulama havuzu yeniden başlayınca formlar bozulmaz. HTTPS zorunlu (`__Host-` çerezi, `UseHttpsRedirection`); uygulama havuzunun yalnız `Storage/` klasörüne yazma izni olmalı (site köküne yazılamaz): loglar da oradadır, `Storage/private/logs/app` ve `errors` (Serilog, saatlik compact JSON; FTP'den `scripts/deploy/ftp-logs.ps1` okur).
- **Veritabanı (betikle):** `Database/FatihTasci-schema.sql` boş veritabanında bir kez çalıştırılır (yeni kurulum: önce veritabanını oluştur, sonra betik, sonra uygulama; seed katalog, ayarlar ve Yöneticiyi ekler). Şema değişiklikleri `Database/Changes/` altındaki sıra numaralı betiklerle mevcut veritabanlarına (geliştirme ve canlı) elle uygulanır; hangi betiğin hangi ortamda çalıştığı takip edilir. Eski migration'larla kurulmuş veritabanlarında kalan `__EFMigrationsHistory` tablosu artık kullanılmaz, silinebilir.
- Marka logoları `Server/wwwroot/images/brands/{slug}.png` (256×256 PNG, koyu renkli olduğu için açık zeminde gösterilir).
- `JwtSettings:Secret` en az 32 karakter olmalı, yoksa uygulama açılmaz. Panel kullanıcıları `Data/Context/Seed/Account/AccountSeedData.cs`'te; şifre koda düz yazılmaz, `PasswordHasher<UserEntity>` (PBKDF2) özeti yazılır. Seed'deki danışman hesabının (Hasan Korkmaz, `hasan@fatihtasci.com.tr`) şifresi kimsenin bilmediği rastgele bir şifrenin özetidir; panele girmesi için Yönetici şifresini Kullanıcılar sayfasından belirler. Hesap yalnız o Id ya da e-posta veritabanında yoksa eklenir; panelde değişen şifre, rol ve aktiflik ezilmez, seed şifre sıfırlamaz (`SeedAdmin` ayarı ve `ResetPassword` kaldırıldı). `admin@galeri.test` yalnız geliştirmede eklenir (`DevelopmentUsers`, panelin geliştirme girişi).
- `Storage:Root` (varsayılan `Storage`): `public/` `/media` altında sunulur (WebP varyantları, ekspertiz PDF), `private/` sunulmaz (orijinal fotoğraflar).
- Şifreler `PasswordHasher<UserEntity>` (PBKDF2) ile saklanır. Signage'daki MD5 kullanılmaz.
- Panel oturumu: JWT yalnız HttpOnly `__Host-access_token` çerezinde (`Server/Helpers/AuthCookie.cs`); `Authorization` başlığı kabul edilmez, panel token'ı saklamaz. `/api`'ye durum değiştiren istekler `X-Requested-With: XMLHttpRequest` ister (CSRF), bu yüzden panelde istekler `api/axios.ts` üzerinden yapılır. CSP ve diğer başlıklar `Core/Middleware/SecurityMiddleware.cs`'te; vitrine dış kaynak eklenirse CSP'ye de eklenir.

## Kurallar

Signage'ın CLAUDE.md kuralları geçerlidir, şu farklarla:

- **Tenant yok:** `ITenantProvider`, `X-Tenant-Id`, `ignoreTenant` parametreleri yoktur. Denetim alanları `ICurrentUserProvider` ile doldurulur.
- **Dil:** i18next yoktur, Signage kural 8 (no magic strings) geçersizdir. **Metinler doğrudan Türkçe yazılır.** Enum'ların ekranda görünen adları `[Display(Name)]` ile verilir; panel bunları `GET /api/lookups`'tan alır.

### Backend

1. `record` yok, her model `class`.
2. FluentValidation validator'ı aynı dosyada, request modelinin hemen altında (`<Model>Validator`).
3. **Dosya başına tek tip:** her controller, model (request/response DTO) ve entity kendi dosyasında, dosya adı tip adıyla aynı (`BrandsController.cs`, `SaveBrandRequestModel.cs`). Tek istisna validator'dır (kural 2). İlgili olanlar aynı klasörde durur (`Controllers/Api`, `Models/Domain/Catalog`, `Entity/Inventory`); birden çok tip tek dosyada toplanmaz.
4. `Result.Message` metinleri Türkçe ve kullanıcıya gösterilebilir (panel toast'ları bunları gösterir).
5. Yanıtlar `ServiceResultModel<T>` zarfıyla döner; controller her zaman `Ok(result)` döndürür, HTTP durum kodunu `ServiceResultResponseProccesor` `Code`'dan ayarlar. Doğrulama hataları da aynı zarfla gelir (`Data` = alan → mesajlar).
6. `DomainService.Result(...)` ile yalnız mesaj dönerken isimli argüman kullanın: `Result(message: "...")`. Aksi halde generic `Result<T>(T data)` seçilir.
7. Tam nitelikli tip adı yerine `using`.
8. `appsettings.json`, `appsettings.Development.json`, `appsettings.Production.json` anahtarları senkron tutulur.
9. **EF migration yok** (kullanıcı kararı; `Migrations` klasörü ve açılıştaki `Database.Migrate()` kaldırıldı, `dotnet ef migrations` kullanılmaz). Model (entity / `AppDbContext`) değişince aynı commit'te iki betik: `Database/Changes/NNN_Aciklama.sql` (mevcut veritabanına uygulanır, sıra numaralı, tekrar çalıştırılabilir: `IF COL_LENGTH(...) IS NULL`, `IF OBJECT_ID(...) IS NULL` gibi korumalarla) ve yeniden üretilmiş `Database/FatihTasci-schema.sql` (yeni kurulum). Betikler BOM'suz ve yalnız ASCII yazılır (açıklamalar Türkçe ama ç/ş/ğ/ı/ö/ü/İ yok); başlarında `SET QUOTED_IDENTIFIER ON` vb. olur. Geliştirme ve canlı veritabanına betikler elle (SSMS / `sqlcmd -I`) uygulanır.
10. Slug hiçbir yerde elle girilmez: `SlugHelper`. Marka / seri / model adı değişince eski slug `SlugRedirect`'e yazılır (301).
11. Araç sihirbazı kuralları iki tarafta aynıdır: `Core/Models/Domain/Vehicle/Vehicle*RequestModel.cs` ↔ `Admin/src/pages/vehicles/wizard/schemas.ts`. Biri değişirse diğeri de güncellenir.
12. **Roller (bkz. Kararlar):** Yalnız Yönetici'nin yapabileceği uçlara `[Authorize(Roles = RoleNames.Admin)]` eklenir; panelde ilgili menü `adminOnly`, sayfa `AdminRoute` altında olur. Yetki her zaman sunucuda kontrol edilir.

14. Açıklama editörünün renk / hiza sınıfları üç yerde aynıdır: `Admin/src/components/rich-text/rich-text-format.ts` (renk değerleri `rich-text.css`) ↔ `VehicleService.DescriptionClasses` ↔ `Server/wwwroot/css/site.css` (`--tc-*`, `.description`). Yeni renk üçüne birden eklenir; renk değerleri vitrin zeminine göre seçilir ve panel editöründe de aynıdır.

### Panel (Signage kural 9-18 aynen)

- shadcn primitive'leri (ham `<button>`/`<input>` yok), `components/ui` bileşenlerine görünüm class'ı yok (ESLint `gora/no-design-classes`).
